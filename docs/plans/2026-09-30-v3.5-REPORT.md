## 2. Root causes RC1–RC7 — before → after

Evidence paths are from the plan (`docs/plans/2026-09-30-v3.5-class-browser.md`).

| # | Before (root cause) | After (v3.5) | Stream |
|---|---|---|---|
| **RC1** | Mobility OFF in app (`spell7=0`); in-game label showed `true` but in-game toggles could only veto, never enable. Scheduler dropped the slot. | App-wins toggle SSOT: the 14 toggles pack into the Ext3 mask and the companion pushes `/mdb mask <hhhh> <e>` at Start and on change (out of combat); the `[Meta] ConfigVersion` migration turns Mobility ON **once** for a pre-3.5 `[Spells]` config. `ToggleSync.EffectiveMask` uses the Ext3 echo when valid. | T5 |
| **RC2** | Crowd control OFF (`[CrowdControl] Enabled=0`); CC rows fell to the Utility provider and never reached `Use`. | Migration also turns `[CrowdControl] Enabled` ON once; CC rows route through the CC provider and the real opt-in gate instead of the dead Utility fall-through. | T5 / T6 |
| **RC3** | Defensive gap-fill required a plain HP read, which is secret in Midnight; urgency stayed UNKNOWN and the bridge never offered a defensive. | HP-curve urgency fallback: the Ext2 cell-35 rendered band derives urgency when cell 31 G is UNKNOWN, so the Red/Orange gap-fill path can still arm; UNKNOWN-safe gates unchanged. | T0 / T2 |
| **RC4** | One candidate per slot — the first ready+bound entry shadowed the rest even when held by policy (Charge > Heroic Leap, Shadowstep > Vanish/Sprint). | Bridge rotates **all** ready+bound+policy-eligible candidates per tick; `CandidateTracker` is a `(slot, spellId)` last-seen set with TTL `1.5·N·dwell·tickMs` and the scheduler evaluates every candidate in a slot. | T1 / T6 |
| **RC5** | Escape/Movement never reached the Mobility provider — they routed to Defensive (Red-only); Hunter's only mobility (Disengage) was never automatic. | `CandidateProviders.For`: GapCloser/Movement → Mobility; plain Escape → Mobility; an Escape carrying the `emergencyEscape` flag (or a curated manual escape like Vanish) → Defensive Red-only; a curated CC row on the reused interrupt slot → the CrowdControl provider. | T6 |
| **RC6** | Situational abilities only fired on a brief GCD-off tick; a long `RetryBackoff` silenced them. | Scheduler GCD bypass extends Interrupt → Emergency verdicts **and** registry `OffGcd`; backoff/suppression maps are keyed `(slot, stroke, spellId)` so a rotated sibling is not punished for its predecessor's failure; OS-gate/send-count suppression clears on target change or combat transition. | T6 |
| **RC7** | Coverage thin: only 48/3279 abilities had a companion-owned path; Hunter/Shaman had no minor defensive gap-fill. | Per-class verified overlays (`Knowledge/classes/<CLASS>.json`, all 13 classes) + `ClassOverlayLoader` + `AbilityOverrides` store give every spec a curated, browser-visible path; the browser renders tier/ownership/live why-held per row. | S3a–c / S6 |

## 5. Before / after diagrams

### 5.1 Toggle flow

```
BEFORE (v3.3/3.4)
  app toggles ──(local only)──▶ nothing pushed
  addon Toggles ──veto only──▶ effective = companion AND addon
    └─ in-game label could read ON while app slot was OFF → user sees "true",
       ability never fires (RC1); CC gate default OFF (RC2).

AFTER (v3.5, T5)
  app 14 toggles ──▶ ToggleSync.BuildMask (14-bit) ── /mdb mask <hhhh> <e> ──▶
       (out of combat, retry 1.5 s ×2) ──▶ Bridge: app epoch owns the mask
  Bridge ──▶ Ext3 cells 40-42 (mask + epoch + blocked + checksum) ──▶
       companion TryGetToggleMirror ──▶ EffectiveMask (echo wins while valid)
  mismatch ⇒ red "Toggle sync: blocked" badge (fail-open, never a hard fail)
  migration: pre-3.5 [Spells] config ⇒ Mobility + CC ON once
```

### 5.2 Candidate flow

```
BEFORE (RC4)
  slot pool [A ready+bound, B ready+bound, C]
        └─ encode FIRST only ▶ A
  policy holds A ──▶ slot empty for the tick ──▶ B/C starve
  tracker: one stroke per slot ⇒ rotation looks "stale"

AFTER (T1/T2/T6)
  slot pool [A, B, C] ── rotate all ready+bound+policy-eligible──▶
        ┌─────────────┬─────────────┬─────────────┐
        A(held)       B(use)        C(held)         (next tick rotates)
        └─ tracker (slot, spellId) last-seen set, TTL 446 ms (N=3·dwell=3·33)
  scheduler evaluates every candidate; a rotated sibling keeps its own
  (slot, stroke, spellId) failure scope; GCD bypass for Interrupt/Emergency/OffGcd
```

## 6. Honest limits

- **No live retail run here.** Every RC fix and UI change is offline-proven
  only; a passing build/test never closes a "needs retail run" item.
- **Midnight hides values.** RC3's fix rides the Ext2 cell-35 rendered band,
  which is coarse (±3.3% per band) and gamma-dependent; urgency can cross a
  threshold one band early/late. UNKNOWN still fails open conservatively.
- **Overlay taxonomy is curated best-effort.** Overlay rows rest on
  `spell-verification.json`; ids not verified there stay off. Per-talent/
  instance logic grows over time — "every situation" is staged, not promised.
- **Coverage stays 48 companion-owned paths**; the overlays make the *path*
  visible and per-spec, they do not invent new MaxDps authority. The remaining
  ~3076 are delegated to MaxDps by design.
- **Toggle fallback.** If the Ext3 echo is stale/invalid, `EffectiveMask`
  falls back to the app mask (fail-open); an addon OFF still restricts.
- **Positioning/pulls remain the user's**, and CC/AoE/manual-only rules mean
  not every listed ability is automatic.
- Snapshots/smoke are structural artifacts, never behavioural proof.
